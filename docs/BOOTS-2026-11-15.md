# Nexus 7 flo: boot attempts from r9 to 2026-11-16 01:10 CET

All times are CET. Sources:

- **L**: laptop kernel log (`journalctl -k`, `usb 3-1` / `cdc_ncm`). Product strings: `Android`/Google = lk2nd bootloader menu; `Nexus 7 2013`/ASUS = TWRP (adb); `Google Nexus 7 2013`/Asus + `register 'cdc_ncm'` = pmOS USB network gadget (comes up in the initramfs, about 5–10 s into the kernel). `NETDEV WATCHDOG` = the laptop's transmit queue to the tablet stalled for more than 5 s, the signature of a tablet that has stopped servicing USB.
- **TJ**: the tablet's persistent journal (`journalctl --list-boots`), as captured in the session transcript at 18:09.
- **T**: session transcript (`d08a3003….jsonl`), UTC timestamp given as `T hh:mmZ`.
- **S**: `docs/STATUS.md`.

Columns:

- "dtb" says where the device tree came from.
- "mods" means the modules in rootfs `/usr/lib/modules`. The initramfs only carries the USB-gadget and filesystem modules; msm/GPU, panel, sdhci, clocks, cpufreq, tsens and smb347 are built in. Wi-Fi (wcn36xx, mac80211, cfg80211), Bluetooth and netfilter are rootfs modules.
- The cmdline always includes `quiet splash … loglevel=1 msm.fbdev=0 cpuidle.off=1`. Only the governor and any extras are listed. HZ is 100 everywhere except r13.
- "GUI": every boot goes to graphical.target (greetd + phrog/phoc, Plymouth splash) except #28.
- "Pwr": **U** = cable to the laptop (SMB345 input limit 500 mA after reboot unless written by hand); **W** = wall charger (the user moved the cable to the wall at about 18:21–18:23 and back to the laptop at 22:09).
- "USB→WD" is the seconds from the gadget appearing to the first NETDEV WATCHDOG. This is only an **upper bound** on when the hang started. It also depends on when the laptop began sending traffic (see notes).

## Notes and caveats

1. **The watchdog is an upper bound, not a hang time.** It needs traffic from the laptop and fires only after a 5 s stall.
   - r11 hangs (#10–14): the laptop polled with ssh from the moment of reboot, so the hang started at most about 36–47 s after USB up. That is roughly 45–60 s of kernel uptime: the gadget appears about 5–10 s in, and journald starts about 11 s after USB.
   - #21, #24, #26: polling started only 55–80 s after USB up, after a fixed `sleep`. The "80–90 s" figures are an artefact of that delay, not later hangs.
   - #27: the ssh probe at +43 s hung after connecting, so userspace was already unresponsive. This is consistent with an onset in the same 40–60 s window as r11.
2. **#22 and #26/#27 module provenance.** Restoring from TWRP only changes p22: vmlinuz, initramfs and dtb. During #22, rootfs held r13 modules (r13 had been installed; r12 was restored on p22 only). r12 and r13 module code does differ, because of HZ. But #22 lasted 2 min, and the HZ difference only matters for jiffies-based code. Treat #22 as "r12 kernel + r13 modules" too, so it is also a mismatched boot that did not hang. *This deserves a check by the main session: `T 21:49Z` restored only p22, and the r12 reinstall did not happen before the r14 install at 22:52.*
3. **STATUS.md overcounts the r11 hangs.** It lists "13:48 ×2, 14:23, 14:24 e uno successivo" plus 14:13. The laptop log shows only one gadget enumeration between 13:47:48 and 14:06:13 (TWRP plus `error -71` in between), and none of TJ, L or T shows a second hung boot at 13:5x. The actual r11 hang set is 13:48, 14:13, 14:20 and 14:24 (4 boots). STATUS's 14:23 is the 14:20:05 boot.
4. **#16 (17:12).** The persistent journal ends at 17:11:10, about 13 min before the power-cycle. That fits either an idle, unsynced journal or a real hang that the user did not notice. The user says it was alive. Counted as ok, but ambiguous.
5. **r13 "USB network appears then stops, 2/2" (STATUS) is not supported by L for #19/#20.** No USB events exist between 18:22:51 and 22:09:27. The USB evidence belongs only to #21.
6. Hung boots leave essentially nothing in the persistent journal (0–1 s after the flush). "Last message at second 17" (S) is a flush artefact, not the hang time.
